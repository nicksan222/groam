# Add a web route

Routes are independent files. `routeTree.gen.ts` is generated; never hand-edit
it or recreate a central registry.

## File name

Put the file in `apps/web/src/routes/`. Workspace pages use the `_workspace.`
prefix so they share the authenticated shell.

| URL | File |
| --- | --- |
| `/agents/$agentId` | `_workspace.agents.$agentId.tsx` |
| `/issues/` | `_workspace.issues.index.tsx` |
| `/trips/$tripId/ideas/$proposalId` | `_workspace.trips.$tripId.ideas.$proposalId.tsx` |

After adding the file, run `bun run codegen:routes` (or the full `bun run codegen`)
if the tree is not regenerated by `bun run dev`.

## Route file body

Only compose a feature view. Allowed imports: `@/features/*`, `@/lib/*`,
`@tanstack/react-router`, `@groam/*` (not `@groam/ui` — features own UI
imports).

```tsx
import { createFileRoute } from '@tanstack/react-router';
import { AgentDetailView } from '@/features/agents/agent-detail-view';

export const Route = createFileRoute('/_workspace/agents/$agentId')({
  component: AgentDetailPage
});

function AgentDetailPage() {
  const { agentId } = Route.useParams();
  return <AgentDetailView agentId={agentId} />;
}
```

Pass params into the view. Do not fetch Convex, open dialogs, or inline markup
here.

## After the route exists

- Register `useSetAgentContext` in the **feature view** (see
  `register-agent-screen-context`). A coverage test fails if a product page
  omits it.
- Define a **loading state** in the feature view or a composed child (persistent
  shell with `isLoading`, `showLoading`, `useReadyValue`, or `role="status"`
  skeletons — not a swapped `*Loading` tree). `loading-state-coverage.test.ts`
  walks every route file: layouts, outlets, and redirects are skipped from the
  source; any route that renders a `@/features` view must define loading UI.
- If the page should appear in the sidebar, add a nav component (see
  `add-sidebar-nav`).
