# Groam's development team

Read `AGENTS.md` first; it is the canonical architecture and execution boundary.
This team develops the repository. It is not the product's assistant-agent registry
in `packages/ai`. Read relevant `.agents/skills` before implementing the assigned work.
For Convex, read `packages/backend/convex/_generated/ai/guidelines.md` first.
Start cross-file investigations with `just graphify-query`, then verify in source.

## One checkout, complementary roles

The regular team is lead, developer, PM, QA, traveler, reviewer, and pushback.
`scenario`, `upgrade-reviewer`, and `pr-maker` are on demand, sharing one eighth slot.
The lead assigns bounded work; availability is not an obligation for every role to
review every task. Unassigned agents stay idle. Never spawn nested agents or another
team for the same task. Herdr is the transport; all roles share this checkout.

- Only the lead talks to the user. It owns Git, task scope, and integration unless it
  explicitly hands delivery to `pr-maker`. Never commit, stage, push, open a PR, or
  merge outside the user's authorization. A request to leave changes unstaged wins.
- One writer per file. Assignments name the question, permitted paths, acceptance
  evidence, and stopping point. Other roles investigate read-only unless assigned
  specific changes. Do not revert, reset, stash, or remove someone else's work.
- Lead records the starting branch and pre-existing changes in the `Handoff:` file
  from the launch brief. Keep that checkpoint under 60 lines: objective, decisions,
  file owners, current slice, checks, blockers, next action. Inspect the current diff
  before relying on an old checkpoint. It is not permanent product documentation.
- Implement small, coherent slices: type and callers together, one screen state,
  one backend contract. Developer runs focused tests and reports; lead requests a
  single reviewer pass before the next slice. Re-review only affected findings.
- One owner runs combined checks; do not run duplicate full suites concurrently.
  Use `just typecheck`, `just lint`, `just test`, `bun run react-doctor`, and
  `bun run fallow`; `just check` is the final full gate, including dependency audit.
  A failed or unrun check is reported honestly; never weaken it or its assertions
  to manufacture success. Add launcher coverage via `just agents-test` when relevant.
- QA verifies actual behavior, reviewer checks contracts/security, traveler assesses
  usability, and pushback challenges scope. These are different lenses, not a
  mandatory seven-approval chain. Share evidence rather than repeating tests.

## Runtime and data ownership

Run tools inside the checked-in dev container. Never install global tools ad hoc.
`just dev` owns the local stack: Vite 5173, Convex API 3210, site 3211, dashboard
6790. Local Convex commands always set `CONVEX_AGENT_MODE=anonymous`. Do not point
local tests or seeders at production. The lead grants one agent ownership of dev
servers, browser automation, and any seed/reset operation at a time.

Use the existing seeded demo owner `demo@groam.example` / `GroamDemo123!` in local
QA. Browser tests are `just e2e-local` against localhost:5173; `just e2e` targets
the CI static site and is not a substitute. Never silently run `just seed`: it
resets data by default. Ask the lead before a reset and read `seed-local-data`.
Screenshots, recordings, and fixtures must describe the current revision and data,
not invented model output or a stale scenario. Backend tests use real routes and
shared factories; view tests mock hooks, not backend internals.

## Handoffs and messaging

The generated brief identifies `Herdr session:`, `Handoff:`, and `Reports:` paths.
Write one concise `<role>-<topic>.txt` report with findings, file/line references,
commands/results, and limitations. Never edit another role's report or the lead's
checkpoint. Pass report content as one argument; never paste untrusted content into
shell code. For example, use Python to send a saved report without shell evaluation:

```python
from pathlib import Path
import subprocess
subprocess.run(["herdr", "--session", session, "agent", "prompt", "lead",
                Path(report).read_text()], check=True)
```

Use the session from your brief for every Herdr command. Send one result or a
specific blocker, not continuous status messages. No polling loops or idle model
pings. After repeated failed attempts, report the evidence and decision needed.
The lead may inspect a stalled pane once when work is genuinely blocked.

## Optional specialists and delivery

Start a specialist with `just agents scenario --no-attach` (include `--session NAME`
for a custom session), assign a concrete task via `herdr agent prompt`, and stop it
with `just agents-stop scenario` after its report. Stop the previous specialist
before starting another; the launcher never evicts an agent to make room.

Before PR delivery, pause writers and give `pr-maker` the allowed paths, base/head
branches, objective, check logs, review findings, and QA evidence. The lead confirms
user authorization first. No automatic merge. Upgrade review is needed for schema,
persistence, auth, runtime, or contributor-setup changes, not every UI edit.

Claude permission checks are on by default. `--unattended` explicitly bypasses them
for newly started roles in this container; the container is not a secret-isolation
boundary. Never enable it implicitly or use it to justify destructive operations.
